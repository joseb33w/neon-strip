# Neon Strip

A small **open-world neon-desert city** (Las Vegas style) you can **walk and drive** — a Godot
4.6.3 game exported to mobile web. Built on the data-driven RPG chunk-streaming base: a compact
**4x4 grid of chunks** streams in/out around you so a whole city slice stays smooth on a phone
browser. Stylized low-poly neon-desert look (KayKit `kk_city` kit + Quaternius/Kenney flora +
**Meshy-generated hero pieces** + neon emission), with a real **day -> sunset -> night -> sunrise**
cycle so the neon pops after dark.

> Play (preview): the live URL is in the PR description.

## What's in it
- **Walk or drive the Strip.** Third-person avatar (on-screen joystick + WASD), **drag the right
  side of the screen to orbit** the camera (pitch-clamped so it never tilts to the floor). Walk up
  to the parked car, press **Drive** to get in, steer + accelerate, press **Exit Car** to get out.
- **A believable city slice.** A main Strip of casino/hotel towers + big neon signs, side blocks,
  drivable roads, and sandy desert (cacti / palms / rocks) at the edges. Ambient **traffic** on the
  roads and **pedestrians** on the sidewalks. Signature **Meshy** landmarks: a casino façade, a
  Ferris wheel, a grand fountain, plus a **showgirl** and a **valet** you can talk to.
- **3 enterable venues** (Discovered N/3 on the HUD): a 2-floor **casino** (stairs + working
  elevator; playable **slots** + **blackjack** that bet your chips; a dealer + gamblers), a 2-floor
  **club** (lit dance floor + beat + a VIP balcony), and an open-air **fair** with a rideable
  **Ferris wheel**.
- **Talk to people.** USE near an NPC for a short conversation (a live in-character line streams
  from a shared NPC brain).
- **Collect.** Cash, casino chips, and trinkets scattered around — walk over them; the HUD tracks
  **$**, **Chips**, and your **inventory**.
- **Maps.** A corner minimap (city grid + your position/heading + venue markers) and a full-screen
  map (MAP button).
- **Localized sound.** Each place has its OWN sound that fades with distance — casino jingles +
  slot sounds inside the casino, a beat inside the club, traffic by the roads, crowd murmur on the
  Strip, chatter near people, footsteps walking, an engine while driving, desert wind at the edges.
  No single global city-noise loop.
- **Supabase save.** Your last position, discovered venues, and money + chips + items persist to
  Supabase and **survive a refresh**.

## How it's built
| File | Role |
|---|---|
| `main.gd` | grounded third-person avatar, camera, HUD, driving toggle, pickups, neon signs + venue entrances, wires every system, Supabase save blob |
| `world.json` / `quests.json` | the 4x4 city: per-cell ground / props / landmarks / NPCs + the day->night `sky` cycle, streamed by the chunk runtime |
| `chunk_manager.gd` | resident-ring chunk streamer (floor built immediately, scenery streams in); a `paused` flag for interiors |
| `vehicle.gd` | the drivable arcade car (enter/exit, steer, accelerate, engine loop) |
| `interiors.gd` | enter/exit venue interiors (pauses streaming), multi-floor casino + club with stairs + elevator, the open-air fair + Ferris ride |
| `casino_games.gd` | slot machine + blackjack (bet real chips, win/lose) |
| `maps.gd` | corner minimap + full-screen map |
| `ambient.gd` | ambient traffic + pedestrians (distance-culled) |
| `neon.gd` | emissive neon signs / strips / fake-bloom halos |
| `savesys.gd` + `web/bridge.js` | Supabase persistence (deterministic per-user auth -> upsert/select a JSON save blob, RLS-scoped) |
| `rpg_systems.gd` | state: money / chips / inventory / discovered + save serialization |

Streaming, day/night (`weather3d.gd`), localized audio (`audio_manager.gd`), and NPC dialogue
(`interaction.gd`) come from the base template and are driven by the data in `world.json`.

## Backend (Supabase)
One shared Supabase project; this app owns the table `usr_nmexs7bytxq2_neon_strip_saves`
(Row-Level Security scoped to `user_id`, grants to `authenticated` + `service_role`). One row per
user holds a JSON blob `{pos, discovered[], gold, chips, inventory, collected[]}`. The web client
(`bridge.js`) signs in as a deterministic per-user account and reads/writes its own row via the
publishable anon key.

## Building locally
The bulk of the world + all Meshy hero pieces **stream from R2 at runtime** and are not stored here.
The directly-instanced models + the audio are fetched / generated by scripts:
```bash
bash scripts/fetch_assets.sh        # the drivable car + Kenney pedestrian/player models
python3 scripts/generate_audio.py   # the localized Vegas audio loops + SFX (needs numpy)
godot --headless --path . --import
godot --headless --path . --export-release "Web" out/index.html
cp world.json quests.json out/      # loose, fetched at runtime
# serve out/ from a host that also serves /godot-assets/ same-origin (the preview origin does)
```
Render config: GL Compatibility (WebGL2), single-threaded `nothreads` web export — runs in mobile
Safari/Chrome/Firefox.
